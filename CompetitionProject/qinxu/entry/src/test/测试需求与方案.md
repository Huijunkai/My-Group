## 概述

### 项目背景

Qinxu 是一个基于 HarmonyOS 开发的教务系统前端应用，为学生提供课表查询、成绩查询、考试安排、培养计划等功能。测试模块旨在确保应用的稳定性、可靠性和用户体验。

### 测试目标

- ✅ 验证数据模型的正确性和完整性
- ✅ 确保数据存储和读取的可靠性
- ✅ 测试 UI 组件的交互逻辑
- ✅ 验证业务逻辑的正确性
- ✅ 评估应用性能表现
- ✅ 保障用户体验质量

### 技术栈

- **开发框架**: HarmonyOS (ArkTS)
- **测试框架**: Hypium (@ohos/hypium)
- **测试类型**: 单元测试、仪器化测试
- **断言库**: Hypium Expect API
- **运行环境**: DevEco Studio

## 测试类型

### 1. 单元测试 (Unit Test)

#### 定义
单元测试是对应用中最小可测试单元进行验证的测试，通常针对函数、方法或类。

#### 特点
- ✅ 运行速度快
- ✅ 不依赖设备环境
- ✅ 可在开发机器上直接运行
- ✅ 适合测试纯逻辑代码

#### 适用场景
- 数据模型验证
- 业务逻辑测试
- 工具函数测试
- 数据结构测试

### 2. 仪器化测试 (Instrumented Test)

#### 定义
仪器化测试是在真实设备或模拟器上运行的测试，可以访问 HarmonyOS 的完整 API。

#### 特点
- ✅ 运行在真实环境
- ✅ 可访问设备资源
- ✅ 可测试 UI 交互
- ✅ 可测试系统 API

#### 适用场景
- 数据存储测试（Preferences）
- UI 组件测试
- 能力测试（Ability）
- 系统集成测试

## 测试策略

### 测试金字塔

```
        /\
       /  \
      / UI \          仪器化测试
     /------\         (UI交互、系统集成)
    / 集成测试 \       
   /----------\       仪器化测试
  /  单元测试   \      (数据存储、能力测试)
 /--------------\     
/   纯逻辑测试   \     单元测试
------------------    (数据模型、业务逻辑)
```

### 测试原则

#### 1. AAA 模式

```typescript
it('测试用例名称', 0, () => {
  // Arrange - 准备测试数据
  const studentInfo: StudentInfo = {
    studentId: '202101001',
    name: '张三',
    // ...
  };
  
  // Act - 执行测试操作
  const result = processData(studentInfo);
  
  // Assert - 验证结果
  expect(result).assertEqual(expectedValue);
});
```

#### 2. 测试独立性

- 每个测试用例应该独立运行
- 不依赖其他测试用例的执行结果
- 测试之间不应该有副作用

#### 3. 测试命名规范

```typescript
// 使用中文描述测试场景
describe('学生信息数据类型测试', () => {
  it('should_create_valid_StudentInfo', 0, () => {

    console.info('通过：成功创建包含所有字段的学生信息');
  });
});
```

#### 4. 测试覆盖

- ✅ 正常流程测试
- ✅ 异常流程测试

## 运行指南

### 环境准备

1. **安装 DevEco Studio**
   - 下载最新版本的 DevEco Studio
   - 配置 HarmonyOS SDK

2. **项目配置**
   ```json
   // module.json5
   {
     "module": {
       "name": "entry_test",
       "type": "feature",
       "deviceTypes": ["default", "tablet"]
     }
   }
   ```

### 运行单元测试

#### 方式一：DevEco Studio 运行

1. 打开测试文件
2. 点击测试文件左侧的运行按钮
3. 选择运行配置
4. 查看测试结果

#### 方式二：命令行运行

```bash
# 运行所有单元测试
hvigorw test

# 运行特定测试文件
hvigorw test --module DataStore.test

# 运行特定测试套件
hvigorw test --grep "学生信息数据类型测试"
```

### 运行仪器化测试

#### 方式一：DevEco Studio 运行

1. 连接设备或启动模拟器
2. 右键点击 `ohosTest` 目录
3. 选择 "Run 'All Tests'"
4. 查看测试结果

#### 方式二：命令行运行

```bash
# 运行所有仪器化测试
hvigorw test --module entry_test

# 运行特定测试
hvigorw test --module entry_test --grep "ActsAbilityTest"
```

### 查看测试报告

测试完成后，DevEco Studio 会自动显示测试报告：

- ✅ 通过的测试（绿色）
- ❌ 失败的测试（红色）
- ⏭️ 跳过的测试（黄色）

### 常见问题

#### Q1: 单元测试和仪器化测试的区别？

**单元测试**:
- 运行在开发机器上
- 不需要设备或模拟器
- 测试纯逻辑代码
- 运行速度快

**仪器化测试**:
- 运行在设备或模拟器上
- 可访问 HarmonyOS API
- 测试需要设备资源的功能
- 运行速度较慢

#### Q2: 如何选择测试类型？

| 测试内容 | 推荐测试类型 |
|---------|------------|
| 数据模型验证 | 单元测试 |
| 业务逻辑测试 | 单元测试 |
| 工具函数测试 | 单元测试 |
| 数据存储测试 | 仪器化测试 |
| UI 组件测试 | 仪器化测试 |
| 系统集成测试 | 仪器化测试 |

#### Q3: 如何调试测试失败？

1. **查看错误信息**: DevEco Studio 会显示详细的错误信息
2. **使用断点调试**: 在测试代码中设置断点
3. **查看日志输出**: 使用 `console.info()` 输出调试信息
4. **逐步调试**: 注释掉部分代码，逐步定位问题

#### Q4: 如何提高测试性能？

1. **减少重复初始化**: 使用 `beforeAll()` 代替 `beforeEach()`
2. **并行执行测试**: DevEco Studio 支持并行执行
3. **优化测试数据**: 使用最小必要数据
4. **避免不必要的等待**: 合理设置超时时间
